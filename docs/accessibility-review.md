# UX10 accessibility review

Date: 3 October 2026 (Europe/Athens). Baseline: `a31c3c1`; initial working tree clean. No applicable `AGENTS.md` was found in the repository, its source directories, or ancestor directories. README and existing components were read. UX09's floater, focus recovery and footer spacing were preserved.

## Conclusion and implementation boundary

**The evidence does not support WCAG 2.2 Level AA conformance.** Confirmed failures and unverified criteria below prevent that conclusion. The preceding qualitative UX review is not accessibility approval. Zero automated violations is not conformance evidence for the whole site or any whole criterion.

Only the known link improvement was implemented: `.content-link-inline` now has a persistent native underline, centralized as `--link-inline-thickness: 1px` and `--link-inline-offset: 0.2em`. Native `text-decoration-skip-ink: auto` preserves descenders; decoration follows wrapped text rather than drawing a border around a box. README records the final contract. `ContentLink` did not need a markup change. Inherited weight, colours, arrows, arrow-free mail/telephone links, action underlines, navigation, filled actions, destinations and focus rules remain intact. No owner copy or media descriptions were rewritten. No additional audit finding was fixed.

Reference: [W3C WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/) and [WCAG 2.2 normative recommendation](https://www.w3.org/TR/WCAG22/). This review covers Level A and AA; 4.1.1 Parsing is obsolete in WCAG 2.2 and is not counted as a requirement.

## Scope, tools and evidence

Production static export built with Node 24.18.0 / Next 16.3.7, served locally using the existing `npm run start -- --listen 3100`. Preliminary development-server results were repeated against the production export to exclude Next development UI. No deployment was assessed.

Chromium 154.0.8037.92 with existing external Playwright runtime; axe-core 4.11.0 downloaded to `/tmp` from its npm distribution, with A/AA tags for WCAG 2, 2.1 and 2.2. No dependency or lockfile was added. FFprobe established stream types/durations; FFmpeg extracted video storyboards at ten-second intervals. Browser DOM/computed styles, bounding boxes and Chrome DevTools Protocol accessibility trees were inspected. Manual visual inspection of screenshots covered Splat Viewer introductions in both themes and sizes, Careers, wrapping Privacy links, media storyboards, expanded descriptions, footer/theme/floater focus, and layout stress examples. Keyboard events exercised the live browser, not just source markup.

All route cases below were visited in light and dark, at 1280×900 and 320×900 CSS pixels. All received automated scans in the desktop/default state, rendered text colour collection, heading/title/image/control inventory, spacing and resizing probes. Keyboard traversal and skip-link activation covered every route at both widths and themes, with mobile Menu and project descriptions expanded. Chromium accessibility trees were captured for all those traversals. Default and focus states, media posters, disclosures, hover treatments and the floater were examined separately. The 320×256 viewport represents reflow at the CSS viewport equivalent of a 1280×1024 browser at 400%; it is **not actual browser zoom**.

A Control-plus browser-zoom attempt left `innerWidth=1280`, `innerHeight=900`, `devicePixelRatio=1` unchanged. Actual 400% zoom is therefore unverified in this headless environment. No usable browser/native UI surface was exposed through computer-use (browser inventory empty). Orca is installed but not running, and this assessment had no exposed screen-reader interaction/audio session. **No actual screen-reader test was performed.** Accessibility-tree inspection does not substitute for it. Firefox is installed but was not tested; neither Safari nor a physical mobile device was available. OS select popups, all native video submenus/fullscreen modes, touch and speech input remain unverified.

Temporary evidence is in `/tmp/ux10-evidence/`: `audit.cjs`, `states.cjs`, `resize.cjs`, `extra.cjs`, `targets.cjs`/`recovery.cjs`, their JSON/log results, screenshots, CDP trees and video storyboards. These are local, ephemeral audit artifacts, not a permanent test suite. This report retains the measurements, findings and reproduction procedures needed for review.

## Contrast measurements

Measurements used rendered `getComputedStyle` colours and ancestor backgrounds, converting CSS colours to sRGB RGBA in a canvas, alpha-compositing foregrounds over their actual solid background chain, then applying WCAG relative luminance. Hex values below round composited channels to eight bits; ratios retain the calculation before displayed rounding. Image pixels, native controls and moving video overlays are not covered by solid CSS text measurements. Hidden HTML video fallback strings were excluded after identifying them as non-rendered text; their apparent 1.00:1 source-style pair is not a rendered Chromium text failure.

Ordinary text needs **4.5:1**. Large text needs **3:1**: at least 24 CSS px, or at least 18.67px when bold (700+). Inter 600 at 18/20px was conservatively treated as ordinary text. Labels at 12/14px, body at 16/18/20px, and headings at 24–72px were inventoried; no visible solid-background text pair below its threshold was found. This does not verify every video/image text pixel or hidden/native state. Passing link/background contrast does not establish link discoverability; the persistent underline addresses that separately.

## Interaction and layout evidence

- Every route/theme/width traversal transferred skip-link focus to `main-content`, followed document order without positive tabindex or observed traps, and reached footer controls. Mobile Menu and video descriptions opened with Enter/Space; expanded/collapsed states are exposed as disclosure states in Chromium. Hidden menu content was not part of the closed-state tab order. The mobile menu uses native details, not an ARIA application menu; Escape dismissal is an optional usability enhancement, not an automatic AA requirement.
- The accessibility tree exposes banner, named navigation, main, contentinfo, links, headings, named videos, native media play/fullscreen/scrubber controls, the Theme combobox and Back to top button. Decorative marker text is excluded. One H1 and `lang=en` were found on every route. Tree names were inspected; speech output, browse-mode reading and assistive-technology state announcements remain unverified.
- At ordinary 320px width, every route had `scrollWidth=clientWidth=320`. At 320×256, every route also retained 320px width; focused footer Theme control was examined with the floater present. No fully obscured focused control was detected during the normal-size all-route keyboard traversals. Partial visual overlap with a fixed control at arbitrary scroll positions is still possible; this does not alone establish failure of AA 2.4.11, which concerns entirely hidden focused components.
- On Home in both themes/widths, activating the floater with Enter returned `scrollY=0` and focus to “Hypercliq home”. UX09 remains functional. Scrolling to the top while the floater was focused also removed it and returned focus to the logo in all four theme/width combinations. Route-change recovery is supported by source inspection but was not re-exercised for every transition. Keyboard Home/ArrowDown/Enter selected Light, and emulated OS light/dark changes correctly updated System theme.
- At 1280px, doubling each element's computed font size caused no horizontal overflow (all routes remained 1280px). At 320px, this stress probe produced overflow on all routes, including header/footer and long text. This probe leaves fixed line heights unchanged and is not equivalent to a browser's text-only zoom. A separate 200% root-font probe also produced overflow: all routes reached 1286px at a 1280px viewport because desktop navigation remains selected by pixel breakpoints; at 320px, rem-sized logo/control/spacing expand beyond the viewport. These observations warrant resizing follow-up; they are not automatically a 1.4.4 failure without demonstrating loss of content/functionality under supported browser resizing. Real browser text-only zoom remains unverified.
- WCAG spacing overrides (`line-height:1.5`, paragraph margin-bottom `2em`, letter-spacing `.12em`, word-spacing `.16em`, all important) were applied to all routes in both themes at both widths. At 1280px no horizontal overflow was detected. At 320px Home expanded to 337px and Services to 374px; all other pages stayed 320px. Visual inspection shows long headings exceed the viewport, rather than being broken. No clipped/overlapping text loss was established from that alone; horizontal scrolling can reveal it. Combined content/functionality verification is incomplete, so 1.4.12 remains unverified, with a narrow-layout recommendation rather than a speculative failure.
- Inline metrics were verified on Splat Viewer, Careers, Privacy and Terms in both themes at both widths: 1px, 3.6px offset for 18px text / 3.2px for 16px; weight 400 retained; underline persists on hover, focus outline unchanged. Privacy's long external link spans lines, keeping the final word/↗ together; descender ink skipping is `auto`. Careers email has no arrow. Screenshots show recognizable native underlines in both themes on desktop/mobile.
- Target inventory includes 48×48 floater, 160×32 home logo, approximately 80×58 mobile Menu at 320px (label and marker wrap), native Theme select about 88×29, large project cards and padded primary action. Short 14px navigation/footer links need the 2.5.8 spacing exception; inline prose links have the inline exception. A 24px-diameter circle centered on each undersized non-inline author target was checked against other target rectangles (or the circles of other undersized targets) across all routes/themes at both widths with disclosures expanded. No collision was found in these 80 cases. Arbitrary scroll positions, resized/spacing overrides and intermediate widths were not exhaustively checked. Native unmodified media controls have the user-agent exception. 44×44 is AAA 2.5.5, not the AA minimum.

## Project checks and remaining limits

Existing `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run build`, and `npm run smoke` passed after the inline change. Smoke checked 21 exported pages and 18 sitemap URLs. Formatting was run again after adding this report. No permanent audit dependency, commit, push, publish or deployment was performed.

The automated scan found zero A/AA violations on 40 desktop route/theme cases, with incomplete `color-contrast` and `video-caption` checks. Expanded/mobile states were examined through keyboard, screenshots and trees, not an exhaustive axe scan of every combination. Neither that result nor the successful inline regression checks overrides the confirmed failures. Actual screen-reader testing, native text zoom/400% browser zoom, other browser engines, physical devices, complete media alternatives/flash/contrast analysis and exhaustive target/state coverage remain required before any conformance determination.
